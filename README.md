# 回溯 · Retrospection

一个可直接加载的 Chrome Manifest V3 插件。为每个输入框保留独立的输入历史，按最近 7 天输入次数排序，点击即可回填。

[查看下拉列表实际效果](docs/preview.png) · [查看插件弹窗](docs/popup.png)。截图中的示例记录用于展示交互，正式插件不预置历史数据。

## 安装

无需构建，也无需安装 Node.js。

1. 打开 Chrome 的 `chrome://extensions`。
2. 开启右上角的「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择本项目的 **`extension/` 目录**。如果使用打包文件，先解压 ZIP，再选择包含 `manifest.json` 的目录。
4. 刷新已经打开的网页，点击任意普通输入框即可开始使用。

需要 Chrome 114 或更新版本。Chrome 内置页面、扩展商店和 `file://` 页面不注入此插件；体验页请使用下面的本地 HTTP 服务打开。

## 使用与计次

- **聚焦显示**：仅当输入框为空且有历史时，在下方显示按近 7 天次数排序的前 **20 条**历史，可滚动查看。列表只显示内容和次数，悬浮后显示删除按钮，删除后自动补入下一条。空间不足时显示在上方，滚动和窗口缩放时跟随输入框。
- **按字段和页面上下文识别**：结合输入框特征、所属页签、当前面包屑末级名称和弹窗标题分组。同路由下不同页签、不同业务面包屑或不同标题的弹窗分别保存；上下文和字段相同的同类表单共享历史。不同网站、iframe 和 Shadow DOM 分开保存；同一表单内重复出现的相同字段按序号区分。
- **按频次排序**：每行左侧为历史内容，右侧为最近 7 天次数；次数相同，最近使用的在前。列表宽度随内容自适应，最长 280px；超长内容省略显示，悬停可查看全文。
- **悬浮删除**：鼠标移入某行，该行选中并显示删除按钮。删除不会修改输入框的现有内容，也不会触发回填。
- **点击回填**：点击内容或次数区域，直接填入整个内容，触发网页的 `input`、`change` 事件，并计一次使用。
- **键盘操作**：`↑` / `↓` 选择，`Enter` 回填，`Esc` 收起；方向键选中后单独按 `Delete` 删除该记录。带 Ctrl、Shift、Alt 或 Cmd 的组合键不触发历史回填或删除。未选中历史时保留输入框的原有按键行为。
- **有内容时隐藏**：输入任何内容（包括空格）后立即隐藏历史，点击或按方向键也不会重新弹出；清空输入框后恢复显示。回填完成后自动收起。

「一次输入」指发生实际编辑后，按 Enter、离开输入框或提交表单的一次完成动作；这些动作连续触发只计一次。选择历史记录回填也计一次。仅聚焦、删除记录或网页脚本赋值不计次。多行输入框的普通 Enter 保留换行，离开时记录；也可用 Ctrl/Cmd + Enter 完成。中文输入法选词时的 Enter 不会误触回填。

暂停期间的编辑不会在恢复后补记。清空历史或原生表单重置会取消待记录草稿，较早请求的失败不会将它重新保存；网页取消重置时仍保留草稿。删除记录期间的新编辑正常记录。历史列表在原生模态 `dialog` 内也可直接回填和删除。

七天窗口为**当前时刻之前的滚动 168 小时**，不是自然周。七天前的内容仍保留并显示 `0 次`，排在近期使用的内容之后。重新点击当前输入框或返回页面时刷新次数和列表。网页隐藏、离开或关闭时也会尽力保存尚未完成的编辑。

## 数据与设置

点击工具栏的回溯图标，可直接调整以下设置：

- 暂停或恢复所有网站的记录与历史提示。
- 暂停或恢复当前网站。
- 确认后清空本站历史或全部历史。
- **Chrome 输入建议**：控制原生历史下拉框。首次点击「授权管理」申请可选的 `privacy` 权限，只读取状态；授权后可开启或关闭。此为当前 Chrome 配置的全局设置，会同时影响地址自动填充，不影响插件自己的历史记录开关。受企业策略或其他扩展控制时会显示原因并禁用操作。「恢复原设置」撤销本插件对该偏好的控制。安装或授权本身不会更改 Chrome 设置。

数据仅保存在 `chrome.storage.local`，没有服务器、统计上报、远程脚本或云同步。必需权限只有 `storage`，原生历史全局开关按需申请 `privacy` 权限；内容脚本在 HTTP/HTTPS 页面运行，以识别输入框并提供回填。插件保留网页原有的 `autocomplete` 属性，原生建议由全局开关和网页自身设置共同决定。数据不是加密保险箱，卸载插件会移除数据。

密码、验证码、银行卡等通过字段类型、`autocomplete`、名称和标签识别的敏感字段默认跳过；只读、禁用字段和无痕页面也不记录。敏感字段识别属于启发式判断，网站可用 `data-retrospection="off"` 排除整个区域；用户也可暂停该网站。

每组历史在本地最多保存最近使用的 **100 条不同内容**，新增第 101 条时淘汰最久未使用的记录。同类输入框共用这份额度；重复使用已有内容只更新次数和最后使用时间。下拉框只展示排名前 **20 条**，未展示的记录仍保存在本地，使用次数提高后可进入列表。每条最多 **4,000 个 UTF-16 字符**，空白内容不保存。输入时保留原始大小写、空格及换行。

## 输入框如何区分

识别范围由网站来源（协议、主机与端口）、iframe 和 Shadow DOM 确定。在此范围内，优先使用显式的 `data-retrospection-key`；否则结合输入框类型、稳定 `id`、`name`、关联标签和有含义的占位文本识别。常见框架生成的 ID、UUID 和时间戳式标识会被过滤，标签会移除必填星号和末尾冒号。

字段特征之外，还组合以下可识别的上下文：所属页签及其嵌套层级、当前面包屑末级名称、弹窗标题。使用 ARIA 关联以及 Ant Design、Element、Bootstrap 等常见组件结构，不写死业务名称。关联节点的动态 ID 只用于找到文本，不写入识别结果；徽标计数、关闭按钮和隐藏导航不参与文本识别。面包屑只使用末级，避免父级项目或字典实体名称变化将同类字段拆开。

挂在 `body` 下的弹窗会在出现时记住打开按钮所属的页签，稍后首次输入仍保留来源；弹窗复用、键盘打开和嵌套弹窗也使用该来源。从弹窗内页签打开子弹窗时，会继承该层页签。存在多个并列页签组且无法确定所属关系时，不猜测页签。没有可识别上下文时沿用输入框特征分组；没有稳定字段特征时按页面地址和 DOM 位置兜底。同一表单或字段容器内的重复字段按出现序号区分。

聚焦或重新点击输入框时识别，连续输入复用本次结果。弹窗来源在打开操作时采集，随后最多 5 秒短暂监听相关 DOM 变化，只检查发生变化的子树；窗口结束或页面导航后停止监听。出现时保存的来源不受首次输入时间影响。没有打开操作、或超过捕获窗口才出现的弹窗，使用可识别的当前页面上下文兜底。网站可通过显式键稳定字段特征或主动区分同名字段；显式键也受页面上下文约束：

```html
<input data-retrospection-key="project-search" />
<section data-retrospection="off">不记录此区域内的输入框</section>
```

没有新增页面上下文的字段继续使用原存储键，并兼容最早按字段路径保存的历史。启用页签、面包屑或弹窗标题分组后，旧版仅按字段保存的记录可能已经混合多个业务场景，因此不自动复制或归入新分组；旧数据仍保留。更早版本按标题或页签保存的记录也保留原样，不猜测无法反推的哈希键。

支持常见文本、搜索、邮箱、网址、电话、数字输入框、textarea 和普通 contenteditable。复杂富文本编辑器的回填是否被接受取决于其自身的状态管理；封闭的 Shadow DOM 无法访问。

## 本地体验

在仓库根目录运行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

加载插件后打开 <http://127.0.0.1:4173/demo/>。体验页没有模拟历史数据，列表由实际插件记录与显示。

## 开发与验证

运行时使用原生 JavaScript，无第三方依赖。开发测试使用 Node.js 22+ 和 Playwright：

```sh
npm install
npx playwright install chromium
npm run test:all
```

也可单独执行各组检查：

| 命令 | 检查范围 |
| --- | --- |
| `npm run check` | JavaScript 语法、JSON、源码行尾空白、清单引用文件 |
| `npm test` | 7 天滚动计次、排序、100 条淘汰、原文保留、迁移合并、并发写入、权限、损坏数据和失败重试 |
| `npm run test:browser` | 空框显示、20 条展示、回填、删除、键盘、真实输入法切换、焦点保留、多行编辑、刷新持久化、跨域 iframe、暂停清空、异步请求与设置页 |
| `npm run test:fields-browser` | 稳定键兼容、动态 ID、页签/面包屑/弹窗标题、弹窗来源、重复字段、表单外置字段、Shadow DOM、禁用区域和大表单耗时 |
| `npm run test:lifecycle-browser` | 组合键、暂停恢复、清空与迟到请求、删除期间再输入、原生模态框、重置及取消重置、失败重试、时间窗口与页面往返 |
| `npm run test:native-browser` | Chrome 原生建议的权限、双向切换、持久化、状态监听和恢复原设置 |

浏览器测试以临时配置加载真实插件，在 `test-results/` 输出截图；`field-performance.json` 保存含页签及面包屑的 500 字段表单、40 次识别的耗时采样。耗时只代表当前测试环境，不作为跨机器的硬性通过阈值。测试数据仅存在临时浏览器配置中，完成后删除。

原生设置测试使用原始清单检查未授权状态，拒绝授权分支通过模拟权限申请返回 `false` 验证；真实 Chrome 权限对话框不在自动化范围内。已授权场景仅在临时测试副本中预授予 `privacy` 权限，再通过真实 Chrome API 验证设置行为。

如需指定已有 Chromium，可设置 `RETROSPECTION_CHROMIUM_EXECUTABLE` 为浏览器可执行文件路径。自动化环境为 Chromium；具体业务网站及 Windows Chrome 的手动验收需在相应环境完成。

打包：

```sh
python3 scripts/package.py
```

输出 `dist/retrospection-1.0.0.zip`，只包含扩展运行文件，`manifest.json` 位于 ZIP 根目录。

## 文件结构

```text
extension/
  manifest.json     扩展入口
  background.js     校验消息、串行存储、站点设置
  history.js        滚动时间窗与排序的纯逻辑
  native-history.js Chrome 原生建议的权限、全局设置和控制权处理
  context.js        页签、面包屑、弹窗标题与打开来源识别
  fields.js         字段识别、iframe 命名空间、原生回填
  content.js        输入监听、计次去重、Shadow DOM 下拉列表
  popup.*           工具栏弹窗与数据管理
  icons/            本地图标及 SVG 源文件
demo/               真实输入框体验页
tests/              逻辑、worker、交互、字段和原生设置测试
  fixtures/         测试页面
  helpers/          公共浏览器启动、服务和断言辅助
scripts/            源码检查、图标生成与 ZIP 打包
```

实现参考 Chrome 官方的 [Content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage) 和 [Message passing](https://developer.chrome.com/docs/extensions/develop/concepts/messaging) 文档。保留仓库原有 Apache-2.0 许可证。
